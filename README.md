# RL-Tycoon-Agent

> 레스토랑 경영 시뮬레이션 + 강화학습 에이전트 실험 프로젝트.
> 서빙·음료·배달·종업원·특성 등 10가지 시스템을 갖춘 본격 타이쿤 게임입니다.
> 팀원 5명이 각자 강화학습 브랜치에서 학습을 진행하고, 최고 성능 모델을 `main`에 병합합니다.

# RL-Tycoon-Agent

Pygame 기반 2D 레스토랑 경영 시뮬레이션과 강화학습 실험 프로젝트입니다.

게임 플레이와 RL 학습이 같은 로직을 공유합니다. 플레이어는 손님 응대, 조리, 서빙, 음료, 직원, 특성, 업그레이드를 운영하고, 강화학습 에이전트는 동일한 규칙 위에서 학습합니다.

## 현재 상태 요약

- 엔진: Python 3.12, Pygame 2.6, Gymnasium
- RL 라이브러리: Stable-Baselines3, sb3-contrib, PyTorch
- 맵 크기: 16 x 10 타일
- 타일 크기: 64 x 64 px
- 기본 UI 높이: 120 px
- 기본 게임 속도: 0.2초당 1스텝
- 지원 모드: `human`, `versus`, `watch`, `tournament`
- 지원 RL 알고리즘:
  - `PPO`
  - `DQN`
  - `QRDQN`
  - `A3C`
  - `SAC`
  - `DiscreteSAC`
  - `Dreamer`
  - `MARL`
  - `ModelBased`
  - `CrossPlay`

## Quick Start

```bash
pip install -r requirements.txt
python main.py
```

5060 환경용 패키지 세트가 필요하면 아래도 사용할 수 있습니다.

```bash
pip install -r 5060requirements.txt
```

## 게임 실행

```bash
python main.py
python main.py --mode human
python main.py --mode human --days 60
python main.py --mode versus --model models/ppo_v4/best_model.zip
python main.py --mode watch --model models/ppo_v4/best_model.zip --speed 2
python main.py --mode tournament --speed 3
```

### `main.py` 옵션

| 옵션             | 설명                                                     |
| ---------------- | -------------------------------------------------------- |
| `--mode`         | `human`, `versus`, `watch`, `tournament`                 |
| `--model`        | 학습된 모델 경로. 주로 `versus`, `watch`에서 사용        |
| `--algo`         | 관전 모델 알고리즘 이름. 경로 자동 탐지가 애매할 때 지정 |
| `--speed`        | 관전/토너먼트 속도 배수                                  |
| `--target-money` | 목표 금액 강제 지정                                      |
| `--day-limit`    | 일수 강제 지정                                           |
| `--days`         | `30` 또는 `60`, `--day-limit`의 축약형                   |

## 플레이 모드

### 솔로 모드

- 키보드로 직접 레스토랑을 운영합니다.
- 게임 오버 시 랭킹이 기록됩니다.

### 대결 모드

- 왼쪽은 플레이어, 오른쪽은 AI입니다.
- `--model`로 불러온 모델과 같은 조건에서 경쟁합니다.

### 관전 모드

- 학습된 모델 하나를 전체 렌더링으로 관전합니다.
- 기본 정책은 확률적(`stochastic`)으로 시작합니다.
- 조작:
  - `ESC`: 종료
  - `R`: 종료 후 재시작
  - `D`: 결정적/확률적 정책 전환
  - `↑ / ↓`: 속도 조절

### 토너먼트 모드

- `models/` 아래의 학습된 모델을 자동 탐색해 최대 4개까지 동시에 경쟁시킵니다.
- 알고리즘별 대표 모델을 골라 순위를 매깁니다.
- 기본 정책은 확률적(`stochastic`)으로 시작합니다.
- 창은 축소 렌더링으로 표시됩니다.
- 조작:
  - `ESC`: 종료
  - `R`: 종료 후 재시작
  - `D`: 결정적/확률적 정책 전환
  - `↑ / ↓`: 속도 조절

## 핵심 게임 로직

### 기본 운영 흐름

1. 손님이 입장하거나 대기열에 합류합니다.
2. 빈 테이블이 있으면 착석합니다.
3. 주문을 받습니다.
4. 주방에서 음식이 조리됩니다.
5. 바텐더가 있으면 음료 주문이 추가될 수 있습니다.
6. 플레이어 또는 직원이 음식/음료를 전달합니다.
7. 결제와 팁이 정산됩니다.
8. 손님 만족도가 평점과 최종 점수에 반영됩니다.

### 점수 체계

- `net_profit`: 현재 구현상 판매 총수입 기준 누적값
- `shop_rating_stars`: 5점 만점 환산 평점
- `final_score = net_profit * (1 + shop_rating_stars / 10)`

즉, 순수익과 평점을 동시에 올려야 최종 점수가 커집니다.

### 시간과 승리 조건

- 기본 목표 금액: `1500`
- 기본 제한 일수: `30`
- `--days 60` 또는 `--day-limit 60` 사용 가능
- 하루 길이: 60초

| `3`  | kitchen_counter |
| `4`  | bar_counter     |
| `5`  | trash_can       |

## 손님 유형

손님 유형은 [config/customers.json](config/customers.json)에 정의됩니다.

| ID        | 이름        | 인내심 | 부유도 배수 | 팁 범위 | 등장 가중치 | 평점 해금 조건 |
| --------- | ----------- | ------ | ----------- | ------- | ----------- | -------------- |
| `budget`  | 학생        | 80.0   | 0.8         | 0 ~ 1   | 5           | 0.0            |
| `normal`  | 일반인      | 65.0   | 1.0         | 1 ~ 3   | 4           | 0.0            |
| `tourist` | 관광객      | 58.0   | 1.5         | 3 ~ 8   | 2           | 0.4            |
| `wealthy` | 부유한 손님 | 50.0   | 1.8         | 4 ~ 12  | 2           | 0.5            |
| `vip`     | VIP         | 40.0   | 3.0         | 8 ~ 25  | 1           | 0.7            |
| `critic`  | 평론가      | 32.0   | 2.5         | 10 ~ 35 | 1           | 0.8            |

메모:

- 평점이 높아질수록 상위 고객군이 등장합니다.
- `marketing` 업그레이드는 부유한 손님 비중에 영향을 줍니다.
- 바텐더를 고용하면 일부 주문에 음료가 함께 붙습니다.

- 음료는 바텐더 고용 후부터 의미가 생깁니다.
- 현재 음료 목록:

## 현재 알고리즘 메모

- `PPO`: 현재 프로젝트에서 가장 안정적인 기준선 역할
- `DQN`: 단순 baseline
- `QRDQN`: 이산 행동 공간용 분포적 DQN 비교군
- `DiscreteSAC`: 커스텀 이산 SAC
- `Dreamer`: 세계모델 기반 실험용
- `CrossPlay`: 여러 알고리즘 모델을 상대 풀로 삼아 추가 학습

작은 이산 행동 공간과 보상 shaping 비중이 큰 환경이라, 일반적으로는 Dreamer보다 PPO/QRDQN 계열이 더 잘 맞을 가능성이 큽니다.

## Quick Start

```bash
# 1) 의존성 설치
pip install -r requirements.txt

# 2) 게임 실행 (대화형 메뉴 – 모드/일수 선택)
python main.py

# 3) CLI로 직접 실행
python main.py --mode human                    # 솔로 30일
python main.py --mode human --days 60           # 솔로 60일
python main.py --mode versus --days 30          # 대결 30일 (vs 랜덤 AI)
python main.py --mode versus --days 60          # 대결 60일
python main.py --mode versus --model models/ppo/best_model.zip  # 학습된 AI와 대결

# 4) RL 에이전트 학습 (30일 / 60일)
python -m algorithms.train_launcher --algo PPO                  # 30일 (config 기본)
python -m algorithms.train_launcher --algo PPO --days 60        # 60일
python -m algorithms.train_launcher --algo A3C --days 30        # A3C 30일
python -m algorithms.train_launcher --algo A3C --days 60        # A3C 60일
python -m algorithms.train_launcher --algo DQN --days 60        # DQN 60일
python -m algorithms.train_launcher --algo SAC --days 60        # SAC 60일
```

### 상호작용(Space) 상세 동작

상호작용은 **플레이어가 들고 있는 것**과 **가까이 있는 대상**에 따라 자동 결정됩니다:

| 현재 들고 있는 것 | 가까이 있는 대상      | 결과                        |
| ----------------- | --------------------- | --------------------------- |
| 아무것도 없음     | 주문 대기 중인 테이블 | **주문 받기** (ORDER 획득)  |
| 주문(ORDER)       | 주방 카운터           | **주방에 전달** (조리 시작) |
| 아무것도 없음     | 주방 (READY 있음)     | **음식 수거** (FOOD 획득)   |
| 음식(FOOD)        | 해당 테이블           | **서빙** (결제 발생)        |
| 아무것도 없음     | 바 (READY 있음)       | **음료 수거** (DRINK 획득)  |
| 음료(DRINK)       | 해당 테이블           | **음료 서빙**               |
| 아무것이나        | 쓰레기통              | **아이템 폐기** (손 비우기) |

## 게임 흐름 (How to Play)

플레이어는 레스토랑의 **서버(웨이터)** 역할입니다. 핵심 루프:

```
┌────────────────────────────────────────────────────────────────┐
│  손님 도착 → 주문 받기 → 주방 전달 → 조리 → 음식 수거 → 서빙  │
│  (+ 음료 주문 시: 바에서 제조 → 음료 수거 → 음료 서빙)        │
│  → 결제(음식값 + 팁 + 음료값) → 만족도 기록 → 매장 평점 갱신  │
└────────────────────────────────────────────────────────────────┘
```

### 단계별 상세

1. **손님이 입구에서 등장** → 배정된 테이블까지 걸어감 (🚶 아이콘)
2. **테이블에 도착** → `?!` 아이콘 표시 (주문 대기)
3. **플레이어가 테이블 앞에서 Space** → 주문을 받음 (화면에 `ORDER` 표시)
4. **주방 카운터 앞에서 Space** → 주문 전달, 조리 시작 (진행 바 표시)
5. **조리 완료 시 초록색 `Ready`** → 주방 앞에서 Space → 음식 수거 (`FOOD`)
6. **해당 테이블 앞에서 Space** → 서빙, 결제 발생!
7. 음료를 주문한 손님은 바 카운터에서 별도로 제조·수거·서빙
8. 돈을 모아서 **업그레이드** 구매 → 더 효율적인 운영

## 10가지 게임 시스템 상세

### ① 기본 서빙 흐름

가장 기본적인 게임 루프입니다.

- **손님 스폰**: 만족도 기반으로 8초 간격(기본)으로 입구에서 손님 등장 → 빈 테이블까지 이동 후 착석, 평점이 높을수록 손님이 더 자주 방문, 최대 동시 착석 수 = 활성 테이블 수
- **대기열 시스템**: 테이블이 모두 차면 입구 앞에서 최대 **4명**까지 대기 (FIFO). 대기 인내심 **30초**, 인내심 소진 시 이탈. 테이블 비면 자동 착석.
- **주문→조리→서빙**: 위의 게임 흐름 참조
- **결제 금액**: `음식가격 × 재산배율 + 팁 + 음료가격`
- **순이익 추적**: `net_profit = total_earned - total_spent` (순수익이 해금 조건의 기준)

### ② 팁(Tip) 시스템

서빙 속도에 비례하여 팁이 결정됩니다.

- **팁 공식**: `random(tip_lo, tip_hi) × patience_ratio`
  - `patience_ratio` = 남은 인내심 / 최대 인내심 (0.0 ~ 1.0)
  - 빠른 서빙 → patience_ratio 높음 → 팁 ↑
- **특성 보너스**: 매력적(charming) 특성으로 팁 +30% 추가배율, 팁 항아리(tip_jar)로 기본 팁 +$3
- **손님별 팁 범위**: 학생 $0-1 / 일반인 $1-3 / 관광객 $3-8 / 부유 $4-12 / VIP $8-25 / 평론가 $10-35

### ③ 메뉴 해금 (Food Unlock)

게임 초기에는 커피, 샌드위치, 파스타 3개가 해금됩니다. 스테이크부터 순이익 기준 **자동 해금** 체인이 시작됩니다:

| 메뉴          | 조리시간 | 가격 | 해금조건 (순이익) |
| ------------- | -------- | ---- | ----------------- |
| 커피          | 2초      | $8   | 처음부터          |
| 샌드위치      | 3초      | $12  | 처음부터          |
| 파스타        | 4초      | $18  | 처음부터          |
| 스테이크      | 5초      | $28  | $200              |
| 초밥 세트     | 6초      | $40  | $500              |
| 랍스터        | 7초      | $55  | $1,000            |
| 와규 스테이크 | 8초      | $75  | $2,000            |
| 트러플 코스   | 10초     | $100 | $3,500            |

- 해금은 **순이익(net_profit) 달성 시 자동**으로 이루어짐 (수동 구매 불필요)
- 해금 후 손님이 해당 메뉴를 주문할 수 있게 됨 (가용 메뉴에서 랜덤 선택)

### ④ 요리사 & 주방 확장 (Chef & Kitchen Expansion)

주방은 **조리 슬롯**(=요리사 수)과 **보관 용량**(=주방 타일 수) 두 가지 용량으로 동작합니다.

- 초기 요리사: **1명** (요리사 1명당 요리 1개 동시 제작)
- 초기 주방 타일: **3칸** (완성된 요리 보관 최대 3개)
- **"요리사 고용" 업그레이드**로 요리사 추가 (최대 주방 타일 수까지)
- **"주방 확장" 업그레이드**로 주방 타일 +1 (보관 용량 +1, 요리사 고용 한도 +1)
- 보관이 가득 차면 요리가 끝나도 요리사가 차단됨 (음식 수거 필요)
- **"조리 속도" 업그레이드**로 조리 시간 단축 (+10%/레벨, 최대 3레벨)
- 조리 속도 보너스: 달인(master_chef) 특성으로 조리 시간 -1초/스택
- 주방이 가득 찼을 때 주문을 제출하면 **주문이 거절**됨 (손실 없음)

### ⑤ 테이블 추가 (Buy Table)

- 초기 테이블: **4개** (맵 상단 행)
- **"테이블 추가" 업그레이드**로 최대 **4개 추가** (총 8개까지)
- 새 테이블은 맵 3번째 행 (y=3)에 배치
- 테이블이 많을수록 동시 손님 수 ↑ → 수익 ↑, 하지만 서빙 부담도 ↑
- 테이블 부족 시 대기열에 손님이 쌍이므로 초반에 테이블 업그레이드 중요

### ⑥ 종업원 (Employee)

종업원은 자동으로 주문 받기, 주방 전달, 음식/음료 수거, 서빙을 수행하는 **AI NPC**입니다.

- **고용 조건**: 순이익 $400 이상 + "종업원 고용" 업그레이드 구매 ($200~)
- **최대 2명** 고용 가능
- **이동 속도**: 120 px/s (플레이어 180 px/s보다 느림), 업그레이드로 최대 3단계 강화 가능
- **끼임 방지**: 0.5초 이상 같은 위치에 머무르면 자동 우회 이동
- **행동 딜레이**: 각 동작 실행에 0.8초 소요

**종업원 AI 우선순위** (높은 순):

1. 음식/음료를 들고 있으면 → 해당 테이블에 서빙하러 이동
2. 주문을 들고 있으면 → 주방에 전달하러 이동
3. 주방에 완성된 음식이 있으면 → 주방에서 음식 수거
4. 바에 완성된 음료가 있으면 → 바에서 음료 수거
5. 주문 안 된 손님이 있으면 → 테이블에서 주문 받기

**종업원 상태 머신**: `IDLE` → `MOVING` (목표 좌표로 이동) → `ACTING` (0.8초 동작) → `IDLE`

### ⑦ 특성(Trait) 시스템

**5일마다** 특성 선택 이벤트가 발생합니다. 8가지 특성 중 랜덤 3개가 제시되며, 하나를 선택합니다.

| 특성 ID           | 한글명        | 효과                       | 최대 중첩 |
| ----------------- | ------------- | -------------------------- | --------- |
| `gourmet`         | 고급 음식     | 모든 음식 가격 +$2         | 5회       |
| `master_chef`     | 달인          | 조리 시간 -1초             | 3회       |
| `skilled_server`  | 숙련된 서빙   | 동시 운반 가능 수 +1 (1→2) | 1회       |
| `charming`        | 매력적        | 팁 +30%                    | 3회       |
| `efficient`       | 효율적        | 이동 속도 +15%             | 3회       |
| `popular`         | 인기          | 손님 방문 빈도 +20%        | 3회       |
| `patient_service` | 친절한 서비스 | 손님 인내심 +5초           | 3회       |
| `tip_jar`         | 팁 항아리     | 기본 팁 +$3                | 3회       |

- **중첩 가능**: 같은 특성을 여러 번 선택하면 효과가 누적 (최대 중첩 횟수까지)
- **RL 에이전트**: 자동으로 첫 번째 특성 선택 (`auto_select_trait`)
- **인간 플레이어**: 팝업에서 1/2/3 키로 선택 (닫기 불가, 반드시 선택해야 함)

### ⑧ 음료(Beverage) 시스템

바텐더를 고용하면 바(Bar) 카운터가 활성화되어 음료 서비스가 시작됩니다.

- **활성화 조건**: 순이익 $300 이상 + "바텐더 고용" 업그레이드 구매 ($150)
- **바 카운터 위치**: 맵 우측 하단 (grid_x=7,8 / grid_y=8)
- 손님이 주문 시 **50% 확률**로 음료도 함께 주문
- 음료는 주문 접수 시 **자동으로** 바에서 제조 시작

| 음료       | 제조시간 | 가격 | 해금조건 (순이익) |
| ---------- | -------- | ---- | ----------------- | --- |
| 물         | 1초      | $2   | 처음부터          |
| 주스       | 1.5초    | $5   | 처음부터          |
| 레모네이드 | 2초      | $8   | $500              |     |
| 층테일     | 3초      | $15  | $1,200            |     |
| 와인       | 2.5초    | $20  | $2,000            |     |

- 음료 수거는 바 카운터 앞에서 Space → DRINK 획득 → 해당 테이블에서 Space
- 음식과 별개로 서빙 (둘 다 서빙해야 결제 완료)

### ⑨ 손님 다양성 (Customer Diversity)

총 6종의 손님 유형이 있으며, 매장 평점에 따라 점진적으로 해금됩니다.

| 유형            | 재산배율 | 인내심 | 팁 범위 | 등장 조건 (평점) | 가중치 |
| --------------- | -------- | ------ | ------- | ---------------- | ------ |
| **학생**        | 0.8×     | 80초   | $0~1    | 항상             | 5      |
| **일반인**      | 1.0×     | 65초   | $1~3    | 항상             | 4      |
| **관광객**      | 1.5×     | 58초   | $3~8    | 평점 40%+        | 2      |
| **부유한 손님** | 1.8×     | 50초   | $4~12   | 평점 50%+        | 2      |
| **VIP**         | 3.0×     | 40초   | $8~25   | 평점 70%+        | 1      |
| **평론가**      | 2.5×     | 32초   | $10~35  | 평점 80%+        | 1      |

- **가중치(spawn_weight)**: 등장 확률의 상대적 비중 (Budget 5 vs VIP 1)
- **높은 평점 유지가 핵심** → 부유한 손님 유치 → 수익 극대화

### ⑩ 배달(Delivery) 시스템

배달 기사를 고용하면 배달 주문이 자동으로 들어옵니다.

- **활성화 조건**: 순이익 $800 이상 + "배달기사 고용" 업그레이드 구매 ($180)
- **동작 방식**: 매 10초마다 랜덤 메뉴 아이템이 주방에 자동 제출 → 12초 후 배달 완료 → 돈 수령
- **배달 가격**: 원래 메뉴 가격 × 0.85 (15% 수수료 차감)
- **배달 팁**: $1~5 랜덤
- **주방 공유**: 배달 주문도 일반 주문과 같은 주방을 사용 → 요리사 수 관리 중요!

## 업그레이드 시스템 상세

업그레이드 메뉴는 **U키**로 열고, **Tab키**로 탭을 전환합니다. 3개 탭으로 분류:

### 시설(Facility) 탭

| 업그레이드  | 기본 비용 | 비용 배율 | 최대 레벨 | 해금 조건   | 효과                    |
| ----------- | --------- | --------- | --------- | ----------- | ----------------------- |
| 주방 확장   | $200      | ×2.0      | 3         | 순이익 $200 | 보관 +1, 요리사 한도 +1 |
| 테이블 추가 | $120      | ×1.5      | 4         | 항상        | 새 테이블 설치          |
| 조리 속도   | $120      | ×2.0      | 3         | 순이익 $100 | 조리 속도 +10%/레벨     |

### 인력(Staff) 탭

| 업그레이드    | 기본 비용 | 비용 배율 | 최대 레벨 | 해금 조건   | 효과                     |
| ------------- | --------- | --------- | --------- | ----------- | ------------------------ | --- | --- | --- |
| 요리사 고용   | $150      | ×1.8      | 5         | 항상        | 요리사 +1 (주방 칸 필요) |
| 종업원 고용   | $200      | ×2.5      | 2         | 순이익 $400 | AI 종업원 +1             |     |     |     |
| 바텐더 고용   | $150      | ×1.0      | 1         | 순이익 $300 | 음료 서비스 개시         |     |     |     |
| 배달기사 고용 | $180      | ×1.0      | 1         | 순이익 $800 | 배달 서비스 개시         |     |     |     |
| 직원 속도 업  | $150      | ×2.0      | 3         | 순이익 $300 | 직원 이동속도 +25%/레벨  |     |     |     |

### 메뉴(Menu) 탭

- **개인** 업그레이드 (이동속도 업, 마케팅) + **메뉴 해금**이 표시됩니다
- 이동속도 업: $80 (×1.8배씩 증가), 최대 3레벨, 이동속도 +20%/레벨
- 마케팅: $100 (×1.6배씩 증가), 최대 3레벨, 부유한 손님 확률 +15%/레벨

### 비용 계산 공식

```
실제 비용 = base_cost × (cost_multiplier ^ 현재_레벨)
예: 주방 확장 레벨 0→1: $200 × 2.0^0 = $200
    주방 확장 레벨 1→2: $200 × 2.0^1 = $400
    주방 확장 레벨 2→3: $200 × 2.0^2 = $800
```

## 만족도·평점·점수 체계

### 만족도 (Satisfaction)

각 손님의 만족도는 서빙 완료 시 `patience_ratio`를 기준으로 계산됩니다:

- **patience_ratio > 0.6**: 빠른 서빙 → 만족도 0.8~1.0
- **patience_ratio 0.3~0.6**: 보통 서빙 → 만족도 0.5~0.8
- **patience_ratio < 0.3**: 느린 서빙 → 만족도 0.5 이하
- **손님 이탈(화남)**: 만족도 -1.0 기록 + 벌금 $10

### 매장 평점 (Shop Rating)

- 최근 20건의 만족도를 **이동 평균**으로 계산 (0.0 ~ 1.0)
- 평점이 높을수록 더 부유한 손님 유형이 등장
- 평점이 낮으면 학생/일반인 손님만 옴 → 수익 저하

### 점수 = 순이익 (Net Profit)

- `net_profit = total_earned - total_spent`
- 서빙·배달로 번 모든 돈에서 업그레이드·해금에 쓴 돈을 뺀 **순수익**
- 순이익이 메뉴·업그레이드·음료 해금 조건의 기준

## RL 학습 가이드

### 관측 공간 (Observation Space) — 80차원 연속값

| 구간  | 차원 수 | 내용                                                                           |
| ----- | ------- | ------------------------------------------------------------------------------ |
| 0~3   | 4       | 플레이어: X좌표, Y좌표, 방향, 운반 상태                                        |
| 4~5   | 2       | 운반 상세: 테이블ID, 메뉴ID                                                    |
| 6~9   | 4       | 이동 상태: 벽에 박힘, 콘텍스트 플래그                                          |
| 10~57 | 48      | 테이블 ×8: [점유여부, 손님상태, 메뉴ID, 인내심비율, 음식서빙, 음료서빙]        |
| 58~60 | 3       | 주방: 조리율(요리사 대비), 보관율(타일 대비), 총 부하                          |
| 61~66 | 6       | 랜드마크 좌표: 주방, 바, 쓰레기통                                              |
| 67~68 | 2       | 타겟 방향 (벡터)                                                               |
| 69~71 | 3       | 대기열: 대기율, 첫 손님 인내심, 대기열 만석                                    |
| 72~79 | 8       | 게임 상태: 돈, 일수, 남은시간, 평점, 업그레이드가능, 순이익, 종업원수, 바+배달 |

모든 값은 0.0~1.0으로 정규화됩니다.

### 액션 공간 (Action Space) — Discrete(7)

| 액션        | ID  | 설명                             |
| ----------- | --- | -------------------------------- |
| UP          | 0   | 위로 이동                        |
| DOWN        | 1   | 아래로 이동                      |
| LEFT        | 2   | 왼쪽 이동                        |
| RIGHT       | 3   | 오른쪽 이동                      |
| INTERACT    | 4   | 상호작용 (테이블/주방/바)        |
| NONE        | 5   | 대기                             |
| BUY_UPGRADE | 6   | 가장 저렴한 업그레이드 자동 구매 |

### 보상 함수 (Reward)

Shop.step()은 이벤트 리스트를 반환하고, `ai/reward.py`의 `RewardCalculator`가
`train_config.json`의 가중치를 적용하여 친 보상을 계산합니다.

| 이벤트              | 기본 가중치 | 비고                            |
| ------------------- | ----------- | ------------------------------- |
| 주문 접수           | +8.0        | take_order                      |
| 주방 전달           | +5.0        | submit_kitchen (×전달 수)       |
| 음식 수거           | +5.0        | pickup_food                     |
| 음료 수거           | +3.0        | pickup_drink                    |
| 음식 서빙           | +15.0       | serve_food                      |
| 음료 서빙           | +8.0        | serve_drink                     |
| 손님 결제           | +1.0 × 금액 | customer_payment (음식+팁+음료) |
| 잘못된 테이블       | -2.0        | wrong_table                     |
| 손님 이탈           | -15.0       | lost_customer                   |
| 업그레이드 구매     | +2.0        | buy_upgrade                     |
| 음식 해금           | +0.3 × 가격 | food_unlock                     |
| 쓰레기통 사용       | -1.0        | trash                           |
| 고아 음식 폐기      | +0.5        | trash_orphan (올바른 행동)      |
| 대기 시작           | -0.3        | customer_waiting                |
| 대기 손님 착석      | +3.0        | waiting_customer_seated         |
| 대기 손님 이탈      | -8.0        | waiting_customer_left           |
| 벽 충돌             | -0.1        | blocked_move                    |
| 대기(아무것도 안함) | -0.3        | idle_penalty                    |
| 시간 압박           | -0.02       | time_penalty (매 스텝)          |
| 목표 달성           | +200.0      | win                             |

> **주의**: 보상 가중치는 `config/train_config.json`의 `reward_shaping`에서 조정합니다.
> 게임 코드(core/) 수정 없이 보상 실험이 가능합니다.

## 기술 상세 (Technical Notes)

### 게임 루프 아키텍처

```
60 FPS 렌더링 루프
  ├── tick(dt)        ← 매 프레임: 연속 이동 (WASD/화살표)
  └── update()        ← 0.2초마다: 게임 로직 step (상호작용, 손님, 조리 등)
```

- **타임스텝**: `STEP_INTERVAL = 0.2초` (초당 5 스텝)
- **이동**: `PLAYER_SPEED = 180 px/s`, 충돌 감지 기반 연속 이동
- **상호작용 범위**: `INTERACT_RANGE = 80 px` (가까이 가야 상호작용 가능)
- **하루**: `DAY_LENGTH = 60초` (실시간 1분 = 게임 1일)
- **타일 크기**: `TILE_SIZE = 64 px` (모든 그리드 좌표 × 64 = 픽셀 좌표)
- **그리드**: 16×10 (1024px × 640px 게임 영역 + 120px UI 패널)

### Versus 모드 구조

- **분할 화면**: 왼쪽 = 인간, 오른쪽 = AI (4px 구분선)
- **독립 Shop 인스턴스**: 각각 별도의 게임 상태
- **시간 동기화**: 둘 다 같은 `time_elapsed` 공유
- AI는 매 스텝마다 관측→예측→행동 실행

### 핵심 상수 (settings.py)

| 상수                       | 값   | 설명                       |
| -------------------------- | ---- | -------------------------- |
| `TILE_SIZE`                | 64   | 타일 크기 (px)             |
| `FPS`                      | 60   | 렌더링 프레임레이트        |
| `STEP_INTERVAL`            | 0.2  | 로직 갱신 주기 (초)        |
| `DAY_LENGTH`               | 60.0 | 1일 = 60초                 |
| `CUSTOMER_SPAWN_INTERVAL`  | 8.0  | 손님 배치 간격 (초)        |
| `MAX_CUSTOMERS`            | 4    | 동시 최대 착석 (초기)      |
| `KITCHEN_CAPACITY`         | 1    | 초기 요리사 수 (조리 슬롯) |
| `MAX_WAITING_QUEUE`        | 4    | 대기열 최대 인원           |
| `WAITING_PATIENCE`         | 30.0 | 대기 손님 인내심 (초)      |
| `PLAYER_SPEED`             | 180  | 플레이어 이동속도 (px/s)   |
| `PLAYER_RADIUS`            | 18   | 충돌 반경 (px)             |
| `INTERACT_RANGE`           | 80   | 상호작용 거리 (px)         |
| `EMPLOYEE_SPEED`           | 120  | 종업원 이동속도 (px/s)     |

## 랭킹 시스템

정해진 일수(`day_limit`) 내에 더 많은 돈을 번 플레이어가 높은 순위를 차지합니다.

### 랭킹 기록 데이터

| 필드               | 타입   | 설명                            |
| ------------------ | ------ | ------------------------------- |
| `player_name`      | string | 플레이어 이름                   |
| `money`            | int    | 최종 보유 금액 (랭킹 정렬 기준) |
| `net_profit`       | int    | 순이익                          |
| `day_limit`        | int    | 게임 일수 제한                  |
| `customers_served` | int    | 서빙 완료 손님 수               |
| `customers_lost`   | int    | 이탈 손님 수                    |
| `shop_rating`      | float  | 최종 매장 평점 (0.0~1.0)        |
| `won`              | bool   | 목표 금액 달성 여부             |
| `timestamp`        | int    | Unix timestamp                  |

### 로컬 저장

- 게임 종료 시 자동으로 `data/rankings.json`에 기록
- 같은 `day_limit` 기준으로 `money` 내림차순 정렬
- 게임 오버 화면에서 현재 랭킹 순위 표시

### 서버 연결 (향후 구현)

`core/ranking.py`의 `RankingManager` 클래스에 서버 API 스텁이 준비되어 있습니다:

```python
ranking.submit_to_server(entry)      # POST /api/rankings
ranking.fetch_from_server(day_limit)  # GET /api/rankings?day_limit=30
ranking.sync_with_server()            # 양방향 동기화
```

서버 구현 시 위 메서드에 HTTP 요청 로직만 추가하면 됩니다.

## 쓰레기통 시스템

주방에서 음식을 받았는데 손님이 이미 떠난 경우, **쓰레기통**에서 폐기할 수 있습니다.

### 사용법

- 음식/음료/주문을 들고 쓰레기통 앞에서 **Space/Enter** 상호작용
- 들고 있는 모든 아이템이 폐기됩니다
- 직원도 자동으로 판단: 서빙할 테이블의 손님이 떠났으면 쓰레기통으로 이동하여 폐기

### 위치

- 맵 상단 주방 영역 우측 (기본: grid 13,1)
