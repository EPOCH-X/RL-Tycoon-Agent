## Quick Start

```bash
# 1) 의존성 설치
pip install -r requirements.txt

# 2) 게임 실행 (인간 솔로)
python main.py --mode human

# 3) 인간 vs 랜덤 AI 대결
python main.py --mode versus

# 4) 인간 vs 학습된 AI 대결
python main.py --mode versus --model models/best_model.zip

# 5) RL 에이전트 학습 (config/train_config.json 설정 기반)
python -m ai.train

# 6) 학습 시 일부 파라미터 오버라이드
python -m ai.train --timesteps 500000 --n-envs 8

# 7) 커스텀 설정 파일로 학습
python -m ai.train --config my_train_config.json
```

### CLI 옵션 (main.py)

| 옵션               | 기본값     | 설명                               |
| ------------------ | ---------- | ---------------------------------- |
| `--mode`         | `human`  | 게임 모드 (`human` / `versus`) |
| `--model`        | _(없음)_ | 학습된 모델 경로 (versus 모드용)   |
| `--target-money` | `1500`   | 목표 금액 오버라이드               |
| `--day-limit`    | `30`     | 제한 일수 오버라이드               |

### 맵 레이아웃 구조

```
┌──────────────────────────────────────────────────────────────┐
│  Row 0:  벽 (Wall)                                           │
│  Row 1:  주방 영역 – 주방카운터(3) + 바카운터(2) + 쓰레기통  │
│  Row 2:  통로 (주방↔매장 이동 구간)                          │
│  Row 3:  테이블 (초기 4개, 매장 상단)                        │
│  Row 4~5: 매장 내부 바닥 (플레이어 이동 공간)                │
│  Row 6:  확장 테이블 슬롯 (구매 가능 4개)                    │
│  Row 7~8: 매장 하단 바닥                                     │
│  Row 9:  벽 (Wall)                                           │
└──────────────────────────────────────────────────────────────┘
```

- **상단 = 주방 영역**: 주방 카운터, 바 카운터, 쓰레기통 배치
- **하단 = 매장 내부**: 테이블, 가구 배치 가능 영역
- **쓰레기통**: 손님이 떠난 후 남은 음식을 폐기할 수 있는 시설

### 상호작용(Space) 상세 동작

상호작용은 **플레이어가 들고 있는 것**과 **가까이 있는 대상**에 따라 자동 결정됩니다:

| 현재 들고 있는 것 | 가까이 있는 대상      | 결과                              |
| ----------------- | --------------------- | --------------------------------- |
| 아무것도 없음     | 주문 대기 중인 테이블 | **주문 받기** (ORDER 획득)  |
| 주문(ORDER)       | 주방 카운터           | **주방에 전달** (조리 시작) |
| 아무것도 없음     | 주방 (READY 있음)     | **음식 수거** (FOOD 획득)   |
| 음식(FOOD)        | 해당 테이블           | **서빙** (결제 발생)        |
| 아무것도 없음     | 바 (READY 있음)       | **음료 수거** (DRINK 획득)  |
| 음료(DRINK)       | 해당 테이블           | **음료 서빙**               |
| 아무것이나        | 쓰레기통              | **아이템 폐기** (손 비우기) |

## 게임 흐름 (How to Play)

플레이어는 레스토랑의 **서버(웨이터)** 역할입니다. 핵심 루프:

```
┌────────────────────────────────────────────────────────────────┐
│  손님 도착 → 주문 받기 → 주방 전달 → 조리 → 음식 수거 → 서빙  │
│  (+ 음료 주문 시: 바에서 제조 → 음료 수거 → 음료 서빙)        │
│  → 결제(음식값 + 팁 + 음료값) → 만족도 기록 → 매장 평점 갱신  │
└────────────────────────────────────────────────────────────────┘
```

### 단계별 상세

1. **손님이 입구에서 등장** → 배정된 테이블까지 걸어감 (🚶 아이콘)
2. **테이블에 도착** → `?!` 아이콘 표시 (주문 대기)
3. **플레이어가 테이블 앞에서 Space** → 주문을 받음 (화면에 `ORDER` 표시)
4. **주방 카운터 앞에서 Space** → 주문 전달, 조리 시작 (진행 바 표시)
5. **조리 완료 시 초록색 `Ready`** → 주방 앞에서 Space → 음식 수거 (`FOOD`)
6. **해당 테이블 앞에서 Space** → 서빙, 결제 발생!
7. 음료를 주문한 손님은 바 카운터에서 별도로 제조·수거·서빙
8. 돈을 모아서 **업그레이드** 구매 → 더 효율적인 운영

## 10가지 게임 시스템 상세

### ① 기본 서빙 흐름

가장 기본적인 게임 루프입니다.

- **손님 스폰**: 만족도 기반으로 8초 간격(기본)으로 입구에서 손님 등장 → 빈 테이블까지 이동 후 착석, 평점이 높을수록 손님이 더 자주 방문, 최대 동시 착석 수 = 활성 테이블 수
- **주문→조리→서빙**: 위의 게임 흐름 참조
- **결제 금액**: `음식가격 × 재산배율 + 팁 + 음료가격`
- **순이익 추적**: `net_profit = total_earned - total_spent` (순수익이 해금 조건의 기준)

### ② 팁(Tip) 시스템

서빙 속도에 비례하여 팁이 결정됩니다.

- **팁 공식**: `random(tip_lo, tip_hi) × patience_ratio`
  - `patience_ratio` = 남은 인내심 / 최대 인내심 (0.0 ~ 1.0)
  - 빠른 서빙 → patience_ratio 높음 → 팁 ↑
- **특성 보너스**: 매력적(charming) 특성으로 팁 +30% 추가배율, 팁 항아리(tip_jar)로 기본 팁 +$3
- **손님별 팁 범위**: 알뜰 $0-1 / 일반 $1-3 / 관광객 $3-8 / 부유 $4-12 / VIP $8-25 / 평론가 $10-35

### ③ 메뉴 해금 (Food Unlock)

게임 초기에는 커피, 샌드위치, 파스타 3개가 해금됩니다. 스테이크부터 순이익 기준 해금 체인이 시작됩니다:

| 메뉴          | 조리시간 | 가격          | 해금조건 (순이익) | 해금비용 |
| ------------- | -------- | ------------- | ----------------- | -------- |
| 커피          | 2초      | $8            | 처음부터          | -        |
| 샌드위치      | 3초      | $12           | 처음부터          | -        |
| 파스타        | 4초      | $18           | 처음부터          | -        |
| 스테이크      | 5초      | $28  | $200   | $50               |          |
| 초밥 세트     | 6초      | $40  | $500   | $100              |          |
| 랍스터        | 7초      | $55  | $1,000 | $150              |          |
| 와규 스테이크 | 8초      | $75  | $2,000 | $250              |          |
| 트러플 코스   | 10초     | $100 | $3,500 | $400              |          |

- 해금은 **업그레이드 메뉴 > 메뉴 탭**에서 구매
- 해금 후 손님이 해당 메뉴를 주문할 수 있게 됨 (가용 메뉴에서 랜덤 선택)

### ④ 요리사 & 주방 확장 (Chef & Kitchen Expansion)

- 초기 요리사: **1명** (요리사 1명당 요리 1개만 동시 제작 가능)
- **"요리사 고용" 업그레이드**로 요리사 추가 (최대 주방 칸 수까지)
- 초기 주방 칸: **3칸** → **"주방 확장" 업그레이드**로 칸 추가 (최대 3회)
- 주방 칸 수 = 요리사 고용 한도 (칸이 부족하면 고용 불가)
- **"조리 속도" 업그레이드**로 조리 시간 단축 (+25%/레벨, 최대 3레벨)
- 조리 속도 보너스: 달인(master_chef) 특성으로 조리 시간 -1초/스택

### ⑤ 테이블 추가 (Buy Table)

- 초기 테이블: **4개** (맵 상단 행)
- **"테이블 추가" 업그레이드**로 최대 **4개 추가** (총 8개까지)
- 새 테이블은 맵 3번째 행 (y=3)에 배치
- 테이블이 많을수록 동시 손님 수 ↑ → 수익 ↑, 하지만 서빙 부담도 ↑

### ⑥ 종업원 (Employee)

종업원은 자동으로 주문 받기, 주방 전달, 음식/음료 수거, 서빙을 수행하는 **AI NPC**입니다.

- **고용 조건**: 순이익 $400 이상 + "종업원 고용" 업그레이드 구매 ($200~)
- **최대 2명** 고용 가능
- **이동 속도**: 120 px/s (플레이어 180 px/s보다 느림), 업그레이드로 최대 3단계 강화 가능
- **행동 딜레이**: 각 동작 실행에 0.8초 소요

**종업원 AI 우선순위** (높은 순):

1. 음식/음료를 들고 있으면 → 해당 테이블에 서빙하러 이동
2. 주문을 들고 있으면 → 주방에 전달하러 이동
3. 주방에 완성된 음식이 있으면 → 주방에서 음식 수거
4. 바에 완성된 음료가 있으면 → 바에서 음료 수거
5. 주문 안 된 손님이 있으면 → 테이블에서 주문 받기

**종업원 상태 머신**: `IDLE` → `MOVING` (목표 좌표로 이동) → `ACTING` (0.8초 동작) → `IDLE`

### ⑦ 특성(Trait) 시스템

**5일마다** 특성 선택 이벤트가 발생합니다. 8가지 특성 중 랜덤 3개가 제시되며, 하나를 선택합니다.

| 특성 ID             | 한글명        | 효과                        | 최대 중첩 |
| ------------------- | ------------- | --------------------------- | --------- |
| `gourmet`         | 고급 음식     | 모든 음식 가격 +$2          | 5회       |
| `master_chef`     | 달인          | 조리 시간 -1초              | 3회       |
| `skilled_server`  | 숙련된 서빙   | 동시 운반 가능 수 +1 (1→2) | 1회       |
| `charming`        | 매력적        | 팁 +30%                     | 3회       |
| `efficient`       | 효율적        | 이동 속도 +15%              | 3회       |
| `popular`         | 인기          | 손님 방문 빈도 +20%         | 3회       |
| `patient_service` | 친절한 서비스 | 손님 인내심 +5초            | 3회       |
| `tip_jar`         | 팁 항아리     | 기본 팁 +$3                 | 3회       |

- **중첩 가능**: 같은 특성을 여러 번 선택하면 효과가 누적 (최대 중첩 횟수까지)
- **RL 에이전트**: 자동으로 첫 번째 특성 선택 (`auto_select_trait`)
- **인간 플레이어**: 팝업에서 1/2/3 키로 선택 (닫기 불가, 반드시 선택해야 함)

### ⑧ 음료(Beverage) 시스템

바텐더를 고용하면 바(Bar) 카운터가 활성화되어 음료 서비스가 시작됩니다.

- **활성화 조건**: 순이익 $300 이상 + "바텐더 고용" 업그레이드 구매 ($150)
- **바 카운터 위치**: 맵 우측 하단 (grid_x=7,8 / grid_y=8)
- 손님이 주문 시 **50% 확률**로 음료도 함께 주문
- 음료는 주문 접수 시 **자동으로** 바에서 제조 시작

| 음료       | 제조시간 | 가격          | 해금조건 (순이익) |
| ---------- | -------- | ------------- | ----------------- |
| 물         | 1초      | $2            | 처음부터          |
| 주스       | 1.5초    | $5            | 처음부터          |
| 레모네이드 | 2초      | $8   | $500   |                   |
| 층테일     | 3초      | $15  | $1,200 |                   |
| 와인       | 2.5초    | $20  | $2,000 |                   |

- 음료 수거는 바 카운터 앞에서 Space → DRINK 획득 → 해당 테이블에서 Space
- 음식과 별개로 서빙 (둘 다 서빙해야 결제 완료)

### ⑨ 손님 다양성 (Customer Diversity)

총 6종의 손님 유형이 있으며, 매장 평점에 따라 점진적으로 해금됩니다.

| 유형                  | 재산배율 | 인내심 | 팁 범위 | 등장 조건 (평점) | 가중치 |
| --------------------- | -------- | ------ | ------- | ---------------- | ------ |
| **알뜰 손님**   | 0.8×    | 80초   | $0~1    | 항상             | 5      |
| **일반 손님**   | 1.0×    | 65초   | $1~3    | 항상             | 4      |
| **관광객**      | 1.5×    | 58초   | $3~8    | 평점 40%+        | 2      |
| **부유한 손님** | 1.8×    | 50초   | $4~12   | 평점 50%+        | 2      |
| **VIP**         | 3.0×    | 40초   | $8~25   | 평점 70%+        | 1      |
| **평론가**      | 2.5×    | 32초   | $10~35  | 평점 80%+        | 1      |

- **가중치(spawn_weight)**: 등장 확률의 상대적 비중 (Budget 5 vs VIP 1)
- **높은 평점 유지가 핵심** → 부유한 손님 유치 → 수익 극대화

### ⑩ 배달(Delivery) 시스템

배달 기사를 고용하면 배달 주문이 자동으로 들어옵니다.

- **활성화 조건**: 순이익 $800 이상 + "배달기사 고용" 업그레이드 구매 ($180)
- **동작 방식**: 매 10초마다 랜덤 메뉴 아이템이 주방에 자동 제출 → 12초 후 배달 완료 → 돈 수령
- **배달 가격**: 원래 메뉴 가격 × 0.85 (15% 수수료 차감)
- **배달 팁**: $1~5 랜덤
- **주방 공유**: 배달 주문도 일반 주문과 같은 주방을 사용 → 요리사 수 관리 중요!

### 메뉴(Menu) 탭

- **개인** 업그레이드 (이동속도 업, 마케팅) + **메뉴 해금**이 표시됩니다
- 이동속도 업: $80 (×1.8배씩 증가), 최대 3레벨, 이동속도 +20%/레벨
- 마케팅: $100 (×1.6배씩 증가), 최대 3레벨, 부유한 손님 확률 +15%/레벨

### 비용 계산 공식

```
실제 비용 = base_cost × (cost_multiplier ^ 현재_레벨)
예: 주방 확장 레벨 0→1: $150 × 2.0^0 = $150
    주방 확장 레벨 1→2: $150 × 2.0^1 = $300
    주방 확장 레벨 2→3: $150 × 2.0^2 = $600
```

## 만족도·평점·점수 체계

### 만족도 (Satisfaction)

각 손님의 만족도는 서빙 완료 시 `patience_ratio`를 기준으로 계산됩니다:

- **patience_ratio > 0.6**: 빠른 서빙 → 만족도 0.8~1.0
- **patience_ratio 0.3~0.6**: 보통 서빙 → 만족도 0.5~0.8
- **patience_ratio < 0.3**: 느린 서빙 → 만족도 0.5 이하
- **손님 이탈(화남)**: 만족도 -1.0 기록 + 벌금 $10

### 매장 평점 (Shop Rating)

- 최근 20건의 만족도를 **이동 평균**으로 계산 (0.0 ~ 1.0)
- 평점이 높을수록 더 부유한 손님 유형이 등장
- 평점이 낮으면 Budget/Normal 손님만 옴 → 수익 저하

### 점수 = 순이익 (Net Profit)

- `net_profit = total_earned - total_spent`
- 서빙·배달로 번 모든 돈에서 업그레이드·해금에 쓴 돈을 뺀 **순수익**
- 순이익이 메뉴·업그레이드·음료 해금 조건의 기준

```json
{
```

## 강화학습 설정 분리 (train_config.json)

`config/train_config.json`에 모든 학습 파라미터가 분리되어 있습니다.
**팀원들은 이 파일만 수정하여 자유롭게 실험**할 수 있습니다.

```json
{
  "algorithm": "PPO", // 알고리즘 (현재 PPO만 지원)
  "policy": "MlpPolicy", // 정책 네트워크 (MlpPolicy / CnnPolicy 등)

  "training": {
    "total_timesteps": 200000, // 총 학습 스텝 수
    "n_envs": 4, // 병렬 환경 수 (멀티프로세스)
    "seed": 42, // 랜덤 시드
    "eval_freq": 5000 // 평가 주기 (스텝)
  },

  "hyperparameters": {
    "learning_rate": 3e-4, // 학습률
    "n_steps": 2048, // rollout 길이
    "batch_size": 64, // 미니배치 크기
    "n_epochs": 10, // PPO epoch 수
    "gamma": 0.99, // 할인율
    "gae_lambda": 0.95, // GAE lambda
    "clip_range": 0.2, // PPO 클리핑 범위
    "ent_coef": 0.01, // 엔트로피 계수
    "vf_coef": 0.5, // 가치함수 계수
    "max_grad_norm": 0.5 // 그래디언트 클리핑
  },

  "network": {
    "net_arch": [128, 128], // 히든 레이어 구조
    "activation_fn": "tanh" // 활성화 함수 (tanh / relu / elu)
  },

  "reward_shaping": {
    "take_order": 2.0, // 주문 접수 보상
    "serve_food": 5.0, // 음식 서빙 보상
    "submit_kitchen": 1.0, // 주방 전달 보상 (×전달 수)
    "pickup_food": 1.0, // 음식 수거 보상
    "pickup_drink": 1.0, // 음료 수거 보상
    "serve_drink": 3.0, // 음료 서빙 보상
    "customer_payment": 1.0, // 손님 결제 보상 (×결제금액)
    "lost_customer": -30.0, // 손님 이탈 벌점
    "wrong_table": -2.0, // 잘못된 테이블 서빙 벌점

    "no_upgrade": -0.1, // 업그레이드 실패 벌점
    "win": 200.0, // 승리 보너스
    "trash": 0.5 // 쓰레기통 사용
  },

  "game_overrides": {
    "target_money": null, // 게임 목표 금액 (null = 기본값 $5000)
    "day_limit": null // 게임 일수 제한 (null = 기본값 30일)
  }
}
```

### 설정 변경 추천 실험

| 실험          | 수정할 값                                  | 의도                           |
| ------------- | ------------------------------------------ | ------------------------------ |
| 더 긴 학습    | `total_timesteps: 1000000`               | 충분한 경험 축적               |
| 보상 강조     | `serve_food: 10.0, lost_customer: -50.0` | 서빙 우선순위 & 이탈 방지 강화 |
| 탐험 강화     | `ent_coef: 0.05`                         | 다양한 행동 시도 유도          |
| 깊은 네트워크 | `net_arch: [256, 256, 128]`              | 복잡한 패턴 포착               |
| 짧은 에피소드 | `game_overrides.day_limit: 10`           | 빠른 에피소드 순환             |

## RL 학습 가이드

### 관측 공간 (Observation Space) — 49차원 연속값

| 구간  | 차원 수 | 내용                                                                           |
| ----- | ------- | ------------------------------------------------------------------------------ |
| 0~3   | 4       | 플레이어: X좌표, Y좌표, 방향, 운반 상태                                        |
| 4~5   | 2       | 운반 상세: 테이블ID, 메뉴ID                                                    |
| 6~37  | 32      | 테이블 ×8: [점유여부, 손님상태, 메뉴ID, 인내심비율]                           |
| 38~40 | 3       | 주방: 조리중, 완성, 총 부하                                                    |
| 41~48 | 8       | 게임 상태: 돈, 일수, 남은시간, 평점, 업그레이드가능, 순이익, 종업원수, 바+배달 |

모든 값은 0.0~1.0으로 정규화됩니다.

### 액션 공간 (Action Space) — Discrete(7)

| 액션        | ID | 설명                             |
| ----------- | -- | -------------------------------- |
| UP          | 0  | 위로 이동                        |
| DOWN        | 1  | 아래로 이동                      |
| LEFT        | 2  | 왼쪽 이동                        |
| RIGHT       | 3  | 오른쪽 이동                      |
| INTERACT    | 4  | 상호작용 (테이블/주방/바)        |
| NONE        | 5  | 대기                             |
| BUY_UPGRADE | 6  | 가장 저렴한 업그레이드 자동 구매 |

### 보상 함수 (Reward)

Shop.step()은 이벤트 리스트를 반환하고, `ai/reward.py`의 `RewardCalculator`가
`train_config.json`의 가중치를 적용하여 친 보상을 계산합니다.

| 이벤트          | 기본 가중치  | 비고                            |
| --------------- | ------------ | ------------------------------- |
| 주문 접수       | +2.0         | take_order                      |
| 음식 서빙       | +5.0         | serve_food                      |
| 주방 전달       | +1.0         | submit_kitchen (×전달 수)      |
| 음식 수거       | +1.0         | pickup_food                     |
| 음료 수거       | +1.0         | pickup_drink                    |
| 음료 서빙       | +3.0         | serve_drink                     |
| 손님 결제       | +1.0 × 금액 | customer_payment (음식+팁+음료) |
| 잘못된 테이블   | -2.0         | wrong_table                     |
| 손님 이탈       | -30.0        | lost_customer                   |
| 업그레이드 구매 | +3.0         | buy_upgrade                     |
| 업그레이드 실패 | -0.1         | no_upgrade                      |
| 목표 달성       | +200.0       | win                             |
| 쓰레기통 사용   | +0.5         | trash                           |

> **주의**: 보상 가중치는 `config/train_config.json`의 `reward_shaping`에서 조정합니다.
> 게임 코드(core/) 수정 없이 보상 실험이 가능합니다.

## 기술 상세 (Technical Notes)

### 게임 루프 아키텍처

```
60 FPS 렌더링 루프
  ├── tick(dt)        ← 매 프레임: 연속 이동 (WASD/화살표)
  └── update()        ← 0.2초마다: 게임 로직 step (상호작용, 손님, 조리 등)
```

- **타임스텝**: `STEP_INTERVAL = 0.2초` (초당 5 스텝)
- **이동**: `PLAYER_SPEED = 180 px/s`, 충돌 감지 기반 연속 이동
- **상호작용 범위**: `INTERACT_RANGE = 80 px` (가까이 가야 상호작용 가능)
- **하루**: `DAY_LENGTH = 60초` (실시간 1분 = 게임 1일)
- **타일 크기**: `TILE_SIZE = 64 px` (모든 그리드 좌표 × 64 = 픽셀 좌표)
- **그리드**: 16×10 (1024px × 640px 게임 영역 + 120px UI 패널)

### Versus 모드 구조

- **분할 화면**: 왼쪽 = 인간, 오른쪽 = AI (4px 구분선)
- **독립 Shop 인스턴스**: 각각 별도의 게임 상태
- **시간 동기화**: 둘 다 같은 `time_elapsed` 공유
- AI는 매 스텝마다 관측→예측→행동 실행

### 핵심 상수 (settings.py)

| 상수                         | 값   | 설명                     |
| ---------------------------- | ---- | ------------------------ |
| `TILE_SIZE`                | 64   | 타일 크기 (px)           |
| `FPS`                      | 60   | 렌더링 프레임레이트      |
| `STEP_INTERVAL`            | 0.2  | 로직 갱신 주기 (초)      |
| `DAY_LENGTH`               | 60.0 | 1일 = 60초               |
| `CUSTOMER_SPAWN_INTERVAL`  | 8.0  | 손님 배치 간격 (초)      |
| `MAX_CUSTOMERS`            | 4    | 동시 최대 착석 (초기)    |
| `KITCHEN_CAPACITY`         | 1    | 초기 요리사 수           |

| `INTERACT_RANGE`           | 80   | 상호작용 거리 (px)       |
| `EMPLOYEE_SPEED`           | 120  | 종업원 이동속도 (px/s)   |

### 핵심 룰

1. `AssetManager`가 시작 시 자동 탐색 → **코드 수정 없이** 이미지만 추가하면 전환됨
2. **파일명 = 상태명** (코드에서 해당 이름으로 조회)
3. 스프라이트가 없는 엔티티는 자동으로 **색상 도형**으로 폴백
4. 스프라이트 시트의 프레임 수 = 이미지 너비 ÷ 64

> **DEV_README.md** 에 각 엔티티 이름·상태·색상키의 상세 매핑이 있습니다.

## 랭킹 시스템

정해진 일수(`day_limit`) 내에 더 많은 돈을 번 플레이어가 높은 순위를 차지합니다.

### 랭킹 기록 데이터

| 필드                 | 타입   | 설명                            |
| -------------------- | ------ | ------------------------------- |
| `player_name`      | string | 플레이어 이름                   |
| `money`            | int    | 최종 보유 금액 (랭킹 정렬 기준) |
| `net_profit`       | int    | 순이익                          |
| `day_limit`        | int    | 게임 일수 제한                  |
| `customers_served` | int    | 서빙 완료 손님 수               |
| `customers_lost`   | int    | 이탈 손님 수                    |
| `shop_rating`      | float  | 최종 매장 평점 (0.0~1.0)        |
| `won`              | bool   | 목표 금액 달성 여부             |
| `timestamp`        | int    | Unix timestamp                  |

### 로컬 저장

- 게임 종료 시 자동으로 `data/rankings.json`에 기록
- 같은 `day_limit` 기준으로 `money` 내림차순 정렬
- 게임 오버 화면에서 현재 랭킹 순위 표시

### 서버 연결 (향후 구현)

`core/ranking.py`의 `RankingManager` 클래스에 서버 API 스텁이 준비되어 있습니다:

```python
ranking.submit_to_server(entry)      # POST /api/rankings
ranking.fetch_from_server(day_limit)  # GET /api/rankings?day_limit=30
ranking.sync_with_server()            # 양방향 동기화
```

서버 구현 시 위 메서드에 HTTP 요청 로직만 추가하면 됩니다.

## 쓰레기통 시스템

주방에서 음식을 받았는데 손님이 이미 떠난 경우, **쓰레기통**에서 폐기할 수 있습니다.

### 사용법

- 음식/음료/주문을 들고 쓰레기통 앞에서 **Space/Enter** 상호작용
- 들고 있는 모든 아이템이 폐기됩니다
- 직원도 자동으로 판단: 서빙할 테이블의 손님이 떠났으면 쓰레기통으로 이동하여 폐기

### 위치

- 맵 상단 주방 영역 우측 (기본: grid 13,1)
